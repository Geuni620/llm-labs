한국어 위키백과: 현재까지의 적용 순서

작업 위치: part2/chapter4/korean-wiki
현재 범위: 데이터 다운로드부터 전처리·토큰화·빈도 분석·정수 인코딩·NumPy 저장까지.
실제 모델 학습과 3시간/8시간 결과 비교는 사용자 요청으로 다음 챕터에 이관했습니다.

1. 참고 자료와 원본 분리·보존
   최초 ko_wiki_cleaning.7z 및 강의 코드는 참고용으로 유지했습니다.

2. Hugging Face 원본 다운로드
   FineWiki kowiki의 2025년 8월 스냅샷, Parquet 2개·582,035문서·14개 열입니다.
   공급처·고정 revision·해시는 download_manifest.json에 기록했습니다.

3. 원문 텍스트 형식 확인
   5개 문서의 text를 TXT로 추출했습니다. 전체 처리 입력은 원본 582,035개 문서입니다.

4. 8단계 필터와 문장 분리
   수식 문서, 제목·표·목록·빈 행, 수학기호, 한자 비율, 외국어 괄호,
   문자 비율, 한글 비율, 종결부호를 검사했습니다.
   한국어·숫자 괄호와 D. Watson 같은 이니셜 예외를 보존했습니다.
   결과: 정제 문단 2,618,729개·문장 7,099,328개.

5. 전역 중복 문장 제거
   NFKC와 공백 정규화 기준으로 중복 421,696회를 제거했습니다.
   결과: 문장 6,677,632개·비어 있지 않은 문단 2,496,587개.
   독립 검사에서 같은 정규화 기준의 잔여 중복은 0입니다.

6. Kiwi cong-global 형태소·품사 토큰화
   32개 파일 전체를 처리하고 형태소/품사, 공백 토큰, 문장·문단 경계를 저장했습니다.
   결과: 공백을 포함한 토큰 292,363,011개·고유 종류 1,570,824종.

7. 원래 토큰의 빈도 집계와 시각화
   전체 종류를 내림차순으로 token_frequencies.txt에 저장했습니다.
   순위-등장 횟수 그래프와 빈도 1의 종류 비율·등장량 비율을 제공했습니다.

8. 숫자 토큰 자릿수 분리
   SN/W_SERIAL을 개별 숫자/SN과 구분자/SW로 분리했습니다.
   예: 2025/SN → 2/SN 0/SN 2/SN 5/SN.
   결과: 토큰 302,281,587개·고유 종류 1,484,881종.
   숫자 관련 입력 85,958종은 16개의 분리 토큰으로 표현됩니다.
   기존 토큰 파일은 보존했습니다.

9. 숫자 분리 후 재집계와 OOV 보존율 분석
   token_frequencies.numeric.txt를 만들었습니다.
   K별 토큰 커버리지·문장 유지율·문단 ANY/ALL 유지율을 비교했습니다.
   ANY는 한 문장 이상 남으면 문단 유지, ALL은 모든 문장이 남아야 문단 유지입니다.
   전체 빈도를 기준으로 K=35,328이면 문장 45.54%, 문단 ANY 62.56%, ALL 22.58%입니다.
   이 수치는 탐색용 전체 빈도 사전의 결과이며, 아래 train-only 사전 결과와 다릅니다.

10. 사전 크기와 실행 자원 후보 선정
    보존 곡선과 같은 NPLM 설정의 CPU/MPS 속도 측정으로 K=35,328·CPU를 출발 후보로 선정했습니다.
    K에는 특수 토큰 4개가 포함됩니다. 현재 uint16 저장 상한은 65,536종입니다.
    보존율과 속도로 고른 후보이며 모델 품질의 최적값을 증명한 결과는 아닙니다.

11. 원문 문서별 학습/검증/테스트 분리와 최종 사전 구축
    문단의 원문 문서 ID를 복원해 문서별 98%/1%/1% 해시 분리 규칙을 적용했습니다.
    평가 자료와 겹치는 토큰열을 학습에서 제외했습니다.
    학습 자료만으로 35,328종 사전을 만들고 OOV가 있는 문장 전체를 제외했습니다.
    최소 한 문장이 남는 문단을 유지했습니다.
    최종 학습 후보: 문단 1,529,599개·문장 2,977,860개.
    비교 준비용 10%/25%/100% 부분집합도 원문 문서 단위로 고정했습니다.

12. 고정 ID로 정수 인코딩하고 NumPy 파일 저장
    vocabulary.json의 tokens[id]가 형태소/품사 토큰에 대응합니다.
    기존 .ids.u16을 보존하고 같은 값을 담은 1차원 uint16 .ids.npy 3개를 추가했습니다.
    train.ids.npy: 136,469,327개 ID.
    validation.ids.npy: 1,417,621개 ID.
    test.ids.npy: 1,371,753개 ID.
    문단의 시작·길이·문서 연결 정보는 별도 .paragraphs.npy에 있습니다.
    문단 앞 문맥용 BOS 8개와 문단 끝 EOS 1개를 저장합니다. 문장별 EOS를 넣는 형식은 아닙니다.
    train 배열의 BOS를 제외한 실제 예측 타깃은 124,232,535개이며 EOS는 포함됩니다.
    이 배열들은 OOV 필터를 통과한 자료입니다. 전체 302M 토큰을 모두 담은 배열은 아닙니다.
    npy_corpus.py의 NpyArrayCorpus로 NumPy를 메모리 매핑하여 학습용 컨텍스트·타깃 배치를 읽을 수 있습니다.
    기존 체크포인트에 연결된 코드와 원래 .u16 로더는 보존했습니다.

13. 독립 검증·실제 예시·최종 검토
    전체 토큰·빈도·구조 검증 기록과 전체 그래프 전달 기록을 확인했습니다.
    NumPy의 모든 ID가 기존 정수 배열과 같은지 비교했습니다.
    NumPy 로더의 배치·부분집합·샘플러 재개 호환성과 손상 거부 동작도 모델 계산 없이 검증했습니다.
    숫자 변환의 독립 검증은 전체 구조·해시·빈도 검사와 1,024개 문장 표본 변환 검사입니다.
    실제 저장 문단과 토큰/ID 역변환 예시는 reports/integer-encoding-example.txt에 있습니다.
    현재 챕터의 최종 검토 기록은 reports/final-preprocessing-review.json에 보관합니다.
