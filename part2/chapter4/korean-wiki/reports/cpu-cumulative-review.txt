위키 NPLM CPU 최적화 누적 실험 검토

목적: 7시간이라는 숫자에 억지로 맞추지 않고, GPU 없이 CPU 최적화 방법을 한 가지씩 이해하고 측정합니다.
이 문서는 이미 끝난 JSON 보고서를 읽고 산식만 재계산했습니다. 새 모델·테스트·벤치마크를 실행하지 않았습니다.

고정 조건
Apple M1 CPU, NPLM 6,883,968개 매개변수, 사전 35,328종, 문맥8/임베딩64/은닉128, 배치128, seed42.
학습 자료는 RAM에 올린 위키입니다. 1에포크의 실제 예측 타깃은 124,232,535개이며 저장 ID 136,469,327개와 구분합니다.
OpenMP 팀4 확인, BLAS 스레드 예산4 요청. Accelerate 내부 실제 작업 스레드 수는 확인하지 않았습니다.
AdamW(lr0.001, decay0.01, beta0.9/0.999, eps1e-8), 기울기 노름 상한1.0, warmup2회 후 모델·샘플러 상태 초기화.
설정마다 요청20초를 두 번 측정했습니다. 마지막 update를 마치고 종료하므로 조금 초과한 실제 시간이 있습니다.

변경한 내용
native는 이 CPU에 맞는 코드 생성을 요청합니다. 별도 fast-math 허용 실험과 구분합니다.
OpenMP는 softmax 행, 편향 합산·기울기 노름/클리핑, AdamW 원소 계산을 CPU 스레드로 나눕니다.
리덕션은 여러 숫자를 합계나 최댓값 하나로 모으는 계산입니다. 부분 합을 병합하면 덧셈 순서에 따라 반올림이 달라질 수 있습니다.
AdamW는 기울기의 이동평균·제곱 이동평균으로 가중치를 갱신하고 weight decay를 별도로 적용합니다. 원래부터 사용했고 이번에는 갱신 루프를 병렬화했습니다.
캐시 타일링은 행렬을 블록으로 나누어 데이터를 재사용합니다. 이번64칸 직접 구현과 기존 Accelerate BLAS를 비교했습니다.
다항식 fast-exp는 직접 만든 근사 함수입니다. CPU vvexpf는 Apple 벡터 수학 API입니다. 두 방법은 별도입니다.

코호트A: 누적 조합 비교 — 기준은 O3, mcpu=native 없음
수치는 두 회 처리속도의 중앙값이며, 모든5에포크 시간은 외삽입니다.
O3 기준: 추가 OpenMP 없음: 1,447.35 targets/s; 5에포크 119.21시간; 두 회 외삽 범위 78.30~249.74시간.
  본 코호트의 O3 기준이며, 다음 코호트의 native 기준과 같은 설정이 아닙니다.
native + softmax·리덕션·AdamW OpenMP: 3,909.15 targets/s; 5에포크 44.14시간; 두 회 외삽 범위 43.85~44.43시간.
  O3 기준보다 빠르지만 native 컴파일과 세 OpenMP 옵션을 함께 바꿨으므로 개별 효과를 이 코호트만으로 분해할 수 없습니다.
native·OpenMP + 다항식 fast-exp: 2,763.28 targets/s; 5에포크 62.44시간; 두 회 외삽 범위 41.71~124.17시간.
  다항식 근사 오차는 작았으나 이번 두 회 중앙값은 native·OpenMP보다 낮습니다. 큰 편차가 있어 이 측정으로 추가 채택하지 않습니다.
native·OpenMP + fast-math 허용: 2,130.30 targets/s; 5에포크 81.00시간; 두 회 외삽 범위 44.87~415.91시간.
  전역 fast-math 허용은 이번 두 회 중앙값을 개선하지 못했습니다. 수치 의미를 완화하므로 자동 채택하지 않습니다.
fast-math·OpenMP + 64칸 캐시 타일링: 521.41 targets/s; 5에포크 330.92시간; 두 회 외삽 범위 282.56~399.25시간.
  직접 만든 64칸 타일 행렬곱은 연결된 Accelerate BLAS보다 이번 조건에서 느렸습니다. 타일링 일반의 무효를 뜻하지 않습니다.

코호트B: CPU 벡터 exp 비교 — 기준도 native이며 A와 합치지 않습니다.
native 기준: 추가 OpenMP 없음: 중앙값 2,131.96 targets/s; 5에포크 외삽 80.93시간; 범위 65.01~107.18시간; 회차별 1,609.80 / 2,654.13 targets/s.
native + softmax·리덕션·AdamW OpenMP: 중앙값 4,941.32 targets/s; 5에포크 외삽 34.92시간; 범위 34.72~35.12시간; 회차별 4,969.05 / 4,913.60 targets/s.
native·OpenMP + CPU 벡터 exp(vvexpf): 중앙값 5,488.66 targets/s; 5에포크 외삽 31.44시간; 범위 30.51~32.43시간; 회차별 5,321.07 / 5,656.24 targets/s.

같은 계산량의5에포크 외삽 34.9188 → 31.4367시간: 예상 시간 9.9720% 감소.
softmax 벽시계 8.242677 → 6.644330 ms/update: 19.3911% 감소.

설정당184개 비교, 실패0. 독립 Torch 기준 loss·전체 기울기·클리핑·AdamW 갱신 등을 절대2e-6+상대2e-4 규칙으로 확인한 작은1회 갱신 검사입니다.

해석과 다음 병목
이번 후보 중 native·OpenMP에서 CPU vvexpf를 더한 설정은 같은 코호트의 두 회에서 모두 빨랐습니다. 다음 학습용 비교 기준 후보로 삼을 근거가 있습니다.
단, 최종 모델 품질이 가장 좋다는 뜻은 아닙니다. 20초마다 완료한 갱신 수가 달라 마지막loss를 품질 순위로 해석할 수 없습니다.
vvexpf 이후 순전파·역전파 행렬곱: 8.499147 ms/update, 측정 벽시계의 36.44%.
vvexpf 이후 softmax·교차 엔트로피: 6.644330 ms/update, 측정 벽시계의 28.49%.
vvexpf 이후 기울기 노름·클리핑: 3.368970 ms/update, 측정 벽시계의 14.45%.
vvexpf 이후 AdamW 매개변수 갱신: 3.423010 ms/update, 측정 벽시계의 14.68%.
현재 행렬곱이 가장 큰 구간이므로 호출 형태·행렬 배치·메모리 재사용을 한 번에 하나씩 살펴봅니다. 기존 Accelerate를 비교 기준으로 유지합니다.
softmax도 큰 구간입니다. 합산·정규화 루프나 임시 메모리 이동을 한 가지씩 바꾸고 수치 검증 후 비교할 수 있습니다.
기울기 노름·클리핑의 전체 배열 순회를 줄이거나 병렬 합산 구조를 살펴볼 수 있습니다.
사전·모델·배치 크기 변경은 연산 구현 최적화와 다른 실험입니다. 현재 보고서에서는 값을 바꾸거나 몰래 채택하지 않습니다.

해석의 경계
모든 처리속도는 설정마다 약20초를 두 번 측정한 결과입니다. 전체1에포크나5에포크 학습을 실행하지 않았습니다.
5에포크 시간은 단시간 처리속도를 목표 예측124232535회/에포크에 적용한 외삽입니다. 평가·체크포인트·장시간 발열 및 대기 변화를 반영하지 못합니다.
phase는 호출자 벽시계 시간으로 스케줄링 대기·타이머 비용을 포함합니다. 순수 연산 시간이나 CPU 사용률이 아닙니다.
두 코호트는 기준 컴파일 옵션과 실행 시점·시스템 부하가 다르므로 합쳐서 하나의 단계별 속도 곡선으로 만들지 않습니다.
2회 사이 편차가 큰 설정이 있습니다. 범위는 관측된 두 처리속도의 시간 외삽 최소·최대이며 통계적 신뢰구간이 아닙니다.
20초 동안 완료한 update 수가 다르므로 마지막 학습 loss를 모델 품질 순위로 비교하지 않습니다.
수치 허용오차 통과는 장시간 수렴·생성 품질·완전한 bit 일치를 증명하지 않습니다.
OpenMP4팀은 확인되었지만 Accelerate 내부 실제 작업 스레드 수와 Mac의 다른 작업 반응성은 측정하지 않았습니다.
별도 과거 O0 약316시간과 최신 약31시간을 같은 코호트의 확정10배 향상으로 주장하지 않습니다.
강의3M 모델의 정확한 구조·CPU·배치 설정은 확인되지 않았습니다. 7시간은 참고치이며 목표에 억지로 맞추지 않습니다.

계산식
각 회 처리속도 = 완료한 타깃 예측 수 / 실제 compute 초.
대표 처리속도 = 두 회 처리속도의 중앙값.
5에포크 외삽 시간 = 5 × 124,232,535 / 대표 처리속도 / 3,600.
범위 = 두 회 각각의 속도에서 구한 외삽 시간의 최소·최대. 통계적 신뢰구간이 아닙니다.
처리속도 증가율과 시간 감소율은 분모가 달라 같은 수치가 아닙니다.
