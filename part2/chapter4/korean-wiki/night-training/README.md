# CPU/C 실제 야간 학습

최적화한 C 커널을 사용하는 NPLM 학습기다. 원본 배열을 바꾸거나 이전 14시간 비교 큐를 재개하지 않는다. Python 프로세스 하나가 C ABI를 호출하며, 그 프로세스에는 Torch와 Kiwi를 불러오지 않는다.

2026-10-23 실행은 V35,328 / C8 / D64 / H128 / B512 / FP32 / AdamW / CPU 4스레드다. 문서 분리와 train-only 사전은 기존 `.npy` 코퍼스를 그대로 사용한다. 목표는 2에폭이지만 **06:30 업데이트 중단, 07:00 최종 종료가 우선**이다. 모든 에폭·Loss 수치는 실제 처리한 양으로 보고한다.

프로젝트의 `part2/chapter4/korean-wiki`에서 다음 명령으로 상태를 읽는다. 학습이나 벤치마크를 새로 시작하지 않는다.

```sh
.venv-training/bin/python night-training/status.py
```

현재 실행의 `training-runs/night-cpu-20261022-H128-B512/STOP`을 만들면 다음 미니배치 경계에서 중단하고 가능한 경우 체크포인트를 저장한다. 기존 `training-runs/wiki-k35328/STOP`은 별개의 과거 실행이므로 보존한다. 자동 재시작하지 않는다.

- `run.json`: 입력·사전·라이브러리·소스 해시, 모델 설정과 검증 타깃 지문.
- `progress.json`: 30초 간격 진행률·실제 학습량·시간·열 상태.
- `latest.npz`, `latest.previous.npz`: 가중치·Adam 상태·샘플러·방문 문단 상태·누적 시간. 15분 간격과 주요 경계에서 원자적으로 저장한다.
- `checkpoint-elapsed-3h.npz`, `checkpoint-epoch-1.npz`: 해당 평가 시점에 실제 도달하고 보존 검사가 통과했을 때만 만드는 비교용 상태다. Sidecar JSON에 정확한 평가 시각·실제 경과 시간·타깃 수·해시를 남긴다. `archive_checkpoint.py`는 저장된 상태를 복사하며 모델을 불러오거나 학습·평가를 재실행하지 않는다.
- `metrics.jsonl`: 최초 및 30분 간격의 고정 검증 타깃 16,384개 Loss·PPL, 공백/EOS 제외 지표와 같은 프롬프트 생성 토큰.
- `pilot.json`: 첫 30분의 실제 관찰 기록. 데스크톱 UI 지연을 직접 측정한 값은 아니다.
- `summary.json`: 정상 정리된 실행의 실제 최종 상태. 강제 종료 시 이 파일이 없을 수 있으며, 가장 최근 완전한 체크포인트만 복구 근거가 된다.
- `reports/night-20261022-control.json`: 감독 프로세스의 실제 자식 PID·시작/종료·exit code와 시간별 보고 예약 ID.

재개는 동일한 소스·라이브러리·배열·모델 설정에서만 허용된다. 최신 파일이 손상됐으면 검증을 통과한 이전 파일로 복구하고 손상본을 보존한다. 오늘의 절대 종료 시각이 지난 뒤에는 기존 계획으로 재개하지 않는다. 새 날짜 실행은 별도 계획과 실행 관리 상태를 정한 뒤 진행한다.

열 상태는 5초 간격으로 확인한다. `serious`·전원 부족·감시 오류는 보호 중단을 요청하고 30초 내 정리가 끝나지 않으면 종료한다. `critical`은 5초 내 종료 확인이 없으면 강제 종료한다. 20초 이상 완전한 감시 갱신이 없어도 중단한다. 이는 OS 열 압력 감시이며 온도계·화재 감지기나 하드웨어 안전 보증은 아니다.

`summarize.py`는 실제 프로세스 종료와 감독자의 종료 기록을 확인한 뒤에만 최종 JSON/TXT를 만든다. `decode_generations.py`는 종료 후 별도의 Kiwi 프로세스로 저장된 생성 토큰을 복원하며 학습·평가를 다시 실행하지 않는다. 실행 중 최종 결과 파일을 미리 만들지 않는다.

## 누적 2·3·5에폭 재개 실행

2026-10-23 사용자가 1.512159에폭 상태에서 누적 2·3·5에폭까지의 한 번의 연속 실행과 시간별 보고를 승인했다. `continue_run.py`는 동결된 `run.py --resume`를 별도 `resume-cpu-20261023-H128-B512-to5` 폴더에서 실행한다. 원래 야간 폴더와 과거 중지된 큐는 수정하지 않는다.

- 현재 상태: `.venv-training/bin/python night-training/continue_run.py status --record`
- 감독자 상태와 실제 PID: `reports/resume-20261023-control.json`
- 실제 무갱신 전체 모델 복원 검증: `reports/resume-20261023-resume-verification.json`
- 요청/완료 추적: `reports/resume-20261023-task-checklist.json`
- 시작 명령을 중복 호출하지 않는다. `prepare`는 이미 준비한 폴더를 거부하고 `supervise`는 이미 시작한 제어 상태와 실제 다른 학습기를 거부한다. 전역 학습/속도 측정 잠금도 유지한다.
- 감독자는 실제 `epoch_2`, `epoch_3`, `epoch_5`의 저장 상태와 평가 기록을 결합해 아카이브한다. 모델 종료 뒤에만 전체 배열 독립 검증·숫자 지표·저장 생성 예시 복원을 진행한다. `finalize`는 살아있는 학습기를 거부하며 유효한 산출물을 덮어쓰지 않는다.
- 재개 후 벽시계 경과와 누적 활성 학습기 시간을 구분한다. 원래 야간 평가 곡선의 실제 시점은 이어받고 오프라인 중단 시간은 활성 시간에 더하지 않는다.
- `summarize.py`와 `decode_generations.py`의 `--control`은 새 실행의 종료 검증용이다. 생략하면 기존 야간 실행 경로를 그대로 사용한다.
- 누적 5에폭 완료 또는 고정 보호 상한 중 먼저 도달한 조건으로 중단한다. 보호 중단 뒤 자동 재시작하지 않는다. 실제 비교/곡선 게시/최종 보고가 끝난 뒤 새 제어 파일에 기록된 해당 시간별 모니터만 삭제한다.
