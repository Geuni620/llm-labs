# 한국어 위키 NPLM 작업 규칙

## 커밋

이후 추가 커밋은 `type(nplm): 한국어 설명` 형식으로 목적을 구분한다.

- `feat`: 실행 기능이나 평가 도구를 추가한다. 해당 기능의 회귀 테스트도 함께 포함한다.
- `fix`: 확인된 동작 오류를 수정한다.
- `test`: 독립 검증·회귀 검사만 추가하거나 보강한다.
- `docs`: 실행 결과, 해석, 사용법과 남은 작업을 기록한다.

서로 독립적인 기능과 결과 문서는 커밋을 나눈다. 원본 데이터, 전체 정수 배열,
가중치, 가상환경과 컴파일 산출물은 기존 `.gitignore`에 따라 로컬에 보존한다.
관련 없는 다른 챕터의 변경을 포함하지 않는다.

## 실행과 검증

- Python 도구 이름은 `snake_case.py`, 실험 보고서는 `reports/주제-YYYYMMDD.*` 형식을 사용한다.
- 학습, 평가, 생성, 중복 검색, 코드 테스트의 완료를 서로 구분한다.
- 학습 종료나 Git push를 모델 품질 검증 완료로 표시하지 않는다.
- 최종 평가에는 모델 파일 해시, 사전·배열 해시, 평가 범위와 타깃 수를 기록한다.
- 기존 고정 검증 타깃을 비교할 때는 동일한 선택 해시를 확인한다.
- 전체 validation/test 평가와 고정 표본 평가는 별도 행으로 표시한다.
- Loss/PPL과 다음 토큰 정확도를 문장 전체·사실 정확도로 표현하지 않는다.
- 공백/문단 종료 타깃을 포함한 지표와 이를 제외한 지표를 함께 기록한다.
- 평가로 가중치·Adam·샘플러가 변경되지 않았는지, 원본 파일이 보존됐는지 검사한다.
- 최종 모델을 고른 뒤 test를 평가한다. 그 점수를 보고 같은 test에 맞춰 모델을 다시 선택하지 않는다.
- 선택 당시의 메타데이터와 과거 실행 기록은 보존하고, 후속 검증은 새 보고서로 연결한다.
- 실패·보호 중단·미측정 항목을 완료로 승격하지 않는다.
