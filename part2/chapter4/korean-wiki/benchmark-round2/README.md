# 짧은 NPLM 추가 최적화 비교

기존 원본·동결된 벤치마크·학습 체크포인트·Git index를 보존합니다. 장시간 학습은 다음 챕터로 연기한 상태입니다. 아래 실행은 같은 컴퓨터에서 `cpu-benchmark/.timing.lock`을 이용해 직렬로 수행합니다.

- `run_cpu_threads.py`: 기존 C 바이너리의 4/6/8 스레드 예산 비교. 24개 독립 모델 검사를 통과한 뒤 설정당 512 update를 3번 측정합니다.
- `build_cpu_ilp.py`: 기존 combined 빌드의 Softmax 링크 소스만 Claude가 작성한 `cpu-benchmark/experiments/round2/softmax_ilp.c`로 바꿔 별도 바이너리를 만듭니다. 기존 바이너리를 덮어쓰지 않습니다.
- `run_cpu_ilp.py`: B128에서 기존/ILP를 4/6 스레드로 비교합니다. B256/B512는 학습 조건을 바꾸는 별도 처리량 실험으로 표시합니다.
- `../gpu-benchmark/optimization_round2/`: 기존 Metal clipping에 None gradients와 모델 compilation을 조합하는 후보, 동결된 CPU 기준 검증기의 명시적 어댑터, 별도 측정 실행기입니다.
- `run_budget_model.py` / `confirm_budget_model.py`: 어휘·전체 자료를 유지하고 B512에서 H128/H64를 비교합니다. H64는 모델 용량을 줄인 별도 NPLM이며, 품질이 같다고 가정하지 않습니다. 초기 5~7초 관측을 보존하고 두 모델 모두 공통 작업을 두 배로 늘려 11~15초씩 3회 확인했습니다.
- `capture_budget.c` / `verify_budget.py`: 검증 전용 C 래퍼와 독립 Torch CPU 대조입니다. H128/H64·B512·전체 어휘에서 clip1/.05, 4회 연속 갱신과 gradient NaN poison을 확인했습니다. 128개 전체 배열·스칼라 비교가 기존 허용오차를 통과했습니다.

각 측정은 65,536개의 실제 위키 타깃을 예측합니다. B128은 512 update, B256은 256 update, B512는 128 update입니다. B128의 ILP는 최종 가중치·Adam m1·m2가 기존 구현과 비트까지 일치해야 채택 후보가 됩니다. 배치 크기가 다른 경우에는 최종 상태가 같아야 한다고 가정하지 않습니다.

별도 예산 확인(v2)에서는 두 모델 모두 256 update × B512 = 131,072개 타깃을 처리합니다. H128과 H64는 초기 배열 길이·모델 용량이 다르므로 서로 같은 가중치를 요구하지 않고, 같은 실제 입력 순서를 확인합니다. 전체 2에폭의 중앙값 환산은 각각 약 7.42h / 6.02h입니다. 같은 H128/B512도 앞선 부하 상태에서는 약 10.57h였으므로 8시간 완료 보장이 아닙니다.

1에폭은 실제 학습 타깃 124,232,535회입니다. 3·5에폭 시간은 짧은 관측 처리량으로 계산한 환산이며, 평가·체크포인트·장시간 발열·다른 앱 부하를 포함하는 실제 전체 훈련 시간은 아닙니다. 같은 학습 설정도 실행 시점에 따라 달라질 수 있으므로 서로 다른 코호트의 중앙값으로 개선율을 만들지 않습니다.

Claude 원문과 코드 작성 시점의 NOTES는 계획/가설입니다. 실제 검증·측정 결과는 `../reports/*round2*20261018-v1.json`과 최종 요약을 확인합니다. 특히 수치 허용오차 통과와 짧은 학습 Loss는 장기간 수렴·생성 품질을 증명하지 않습니다.

Intel Ubuntu와 NVIDIA는 현재 동일 작업의 실측 결과가 없습니다. 접속 방식은 사용자가 추후 결정하며, 클라우드를 대여하거나 과금 자원을 생성하지 않습니다. 원격 장치가 준비되면 같은 모델·데이터·초기화·FP32·배치·타깃 수와 장치 동기화를 포함해 측정해야 합니다. Apple vForce/Accelerate 경로는 Linux에서 그대로 빌드할 수 없으므로 OpenBLAS/exp 구현의 차이도 기록해야 합니다.
