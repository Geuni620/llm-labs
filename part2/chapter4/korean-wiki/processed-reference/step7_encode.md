# Step 7. 정수 인코딩

토큰 문자열을 vocab 인덱스(정수)로 변환한다.
이 단계의 출력이 모델 훈련의 직접적인 입력이 된다.

## 왜 필요한가

`tokens_filtered_{VS}/` 파일은 문자열 토큰이므로,
훈련 시 매번 문자열→정수 변환을 반복해야 한다.
한 번 변환해두면 훈련 코드는 정수 배열만 로딩하면 된다.

## 구체적 예시

### 1단계: vocab 사전 구축

`vocab_32768.txt`의 각 행이 곧 인덱스다:

```
행번호  토큰          빈도
─────  ──────────  ──────────
  0    <pad>       0           ← 인덱스 0
  1    <unk>       0           ← 인덱스 1
  2    <bos>       0           ← 인덱스 2
  3    <eos>       0           ← 인덱스 3
  4    <sp>/WS     83925455    ← 인덱스 4
  5    ./SF        6713033     ← 인덱스 5
  ...
  8    다/EF       5366165     ← 인덱스 8
  ...
 16    이/VCP      3209218     ← 인덱스 16
  ...
 21    은/JX       2427025     ← 인덱스 21
  ...
152    이름/NNG    179931      ← 인덱스 152
```

이것을 딕셔너리로 만든다: `{"<pad>": 0, "<unk>": 1, "<bos>": 2, ..., "이름/NNG": 152, ...}`

### 2단계: 토큰 → 정수 변환

`tokens_filtered_32768/part_00.txt` 첫 두 줄 (= 한 문단):

```
<bos> 이름/NNG 은/JX <sp>/WS 못/NNG 이/VCP 지만/EC <sp>/WS 커다랗/VA-I ᆫ/ETM <sp>/WS 석호/NNG 이/VCP 다/EF ./SF
고대/NNG 에/JKB 는/JX <sp>/WS 만/NNB 이/VCP 었/EP 으나/EC ... <eos>
```

각 토큰을 사전에서 찾아 정수로 바꾼다:

```
토큰          →  인덱스
───────────     ─────
<bos>         →      2
이름/NNG      →    152
은/JX         →     21
<sp>/WS       →      4
못/NNG        →   9065
이/VCP        →     16
지만/EC       →     77
<sp>/WS       →      4
커다랗/VA-I   →   4093
ᆫ/ETM        →     12
<sp>/WS       →      4
석호/NNG      →  13351
이/VCP        →     16
다/EF         →      8
./SF          →      5
고대/NNG      →    781     ← 두 번째 줄 시작
에/JKB        →     11
는/JX         →     15
<sp>/WS       →      4
만/NNB        →    468
...
```

### 3단계: flat 배열로 저장

두 줄의 토큰이 하나의 1차원 배열로 이어진다:

```python
>>> import numpy as np
>>> ids = np.load("token_ids_32768/part_00.npy")
>>> ids.shape
(4146114,)          # 이 샤드의 전체 토큰 수
>>> ids.dtype
dtype('uint16')
>>> ids[:20]
array([    2,   152,    21,     4,  9065,    16,    77,     4,  4093,
          12,     4, 13351,    16,     8,     5,   781,    11,    15,
           4,   468], dtype=uint16)
#      <bos> 이름  은   <sp>  못   이   지만  <sp> 커다랗 ᆫ   <sp> 석호  이    다   .   고대  에   는   <sp>  만
#      ────── 첫 번째 줄 ─────────────────────────────────────────────  ──── 두 번째 줄 ────
```

빈 줄(문단 경계)은 배열에 포함되지 않는다. `<bos>`(2)와 `<eos>`(3)가 경계 역할을 한다:

```python
>>> ids[ids == 2][:5]   # <bos> 위치들
array([2, 2, 2, 2, 2], dtype=uint16)
>>> np.where(ids == 3)[0][:5]   # <eos> 위치들
array([  46,  108,  171,  233,  321])
```

## 처리 흐름 (전체)

```
vocab_{VS}.txt                   tokens_filtered_{VS}/part_NN.txt
{토큰→인덱스} 사전 구축           "<bos> 이름/NNG 은/JX <sp>/WS ..."
        │                                      │
        └──────────┬───────────────────────────┘
                   ▼
        [2, 152, 21, 4, ...]  (uint16 배열)
                   │
                   ▼
        token_ids_{VS}/part_NN.npy
```

- 빈 줄(문단 경계)은 건너뜀 — `<bos>`(2)/`<eos>`(3) 토큰이 경계 역할
- 각 샤드의 모든 토큰을 이어붙인 1차원 flat 배열

## dtype: uint16

세 vocab size 모두 uint16 범위(0–65535)에 맞는다:

| vocab size | 최대 인덱스 | uint16 범위 |
|---|---|---|
| 32,768 | 32,767 | 0–65,535 |
| 49,152 | 49,151 | 0–65,535 |
| 65,536 | 65,535 | 0–65,535 |

uint16 = 토큰당 2바이트. 1.22억 토큰 × 2B = ~234MB.

## .npy 포맷

NumPy `.npy`는 헤더 + raw 바이너리 구조:

```
\x93NUMPY + 버전(2B) + 헤더길이 + shape/dtype 텍스트 + padding
────────────────────────────────────────────────────
raw uint16 데이터 (little-endian, 연속)
```

C에서도 헤더를 건너뛴 뒤 `fread`로 `uint16_t*` 배열을 직접 읽을 수 있다.
별도 라이브러리 불필요.

## 입출력

```
입력: vocab_{VS}.txt                       (어휘 사전)
      tokens_filtered_{VS}/part_NN.txt     (32 샤드)
출력: token_ids_{VS}/part_NN.npy           (uint16 1-D, 32 샤드)
```
