# 문장 생성 — 다음 토큰 추첨을 반복하기

[generation.ts](generation.ts)는 트라이그램과 NPLM이 계산한 확률을 같은 방식으로 추첨합니다. 생성 중에는 학습된 가중치를 고정합니다.

## 한 번에 하나의 다음 토큰을 고른다

```text
(<pad>, <bos>) → 주어 추첨
(<bos>, 주어) → 다음 토큰 추첨
(주어, 과일) → 다음 토큰 추첨
...
<eos>가 나오면 종료
```

항상 가장 높은 확률의 토큰만 선택하지 않고 확률에 비례해 추첨합니다. 본문은 최대 20토큰으로 제한하며, 마지막 허용 위치 뒤의 `<eos>`도 확인합니다.

생성 확률은 모델의 계산 결과입니다. 원본 문장을 검색해 다음 단어를 고르지 않습니다. 원본과의 비교는 문장이 만들어진 뒤 분류할 때 수행합니다.

## 생성 후 세 범주로 나눈다

- **학습 원문:** 원래 6개 중 하나이고 `<eos>`로 종료했습니다.
- **새 조합:** 주어·과일·동사의 3토큰 형식이고, 원래 6개에 없으며 `<eos>`로 종료했습니다.
- **오류·미완성:** 나머지 결과입니다. 잘못된 순서, 본문에 나온 특수 토큰, 길이 제한 종료 등도 포함합니다.

3주어 × 3과일 × 2동사로 형식에 맞는 조합은 총 18개입니다. 학습 원문 6개 외에 새 조합은 최대 12종입니다. 분류 규칙은 생성 후에만 적용하며, 생성 후보를 문법에 맞게 강제 제한하지 않습니다.

## 모델마다 10,000개를 생성한 결과

| 모델 | 학습 원문 | 새 조합 | 오류·미완성 |
| --- | ---: | ---: | ---: |
| 트라이그램 MLE | 10,000 (100.00%) | 0 (0.00%) | 0 (0.00%) |
| 트라이그램 add-k, k=0.01 | 8,068 (80.68%) | 42 (0.42%) | 1,890 (18.90%) |
| NPLM D2·H8·lr0.3 | 9,893 (98.93%) | 17 (0.17%) | 90 (0.90%) |

NPLM은 학습 2,000회·학습 seed 123의 모델이고, 추첨 seed는 2026입니다. 17개는 17종이 아니라 6종이 중복을 포함해 나온 횟수입니다. 원문과 다른 107개를 모두 새 조합으로 세면 오류 90개까지 포함하게 됩니다.

스무딩 모델보다 새 조합이 적다는 사실만으로 NPLM의 일반화가 나쁘다고 결론 낼 수는 없습니다. 원문 적합도, 오류 비율, 새 조합의 종류를 함께 봅니다. 형식에 맞는 새 조합이 실제 의미나 취향까지 올바르다는 보장도 없습니다.

## 다음 단어 확률과 전체 문장 확률은 다르다

대표 NPLM은 `(철수는, 바나나를)` 뒤의 좋아해에 약 99.89%를 주었습니다. 하지만 먼저 `(<bos>, 철수는)` 뒤에서 바나나를이 추첨되어야 하고, 이 확률은 약 0.22%였습니다.

전체 문장 확률은 시작부터 `<eos>`까지 각 단계의 확률을 곱한 값입니다. 특정 문맥에서 좋아해의 확률이 높아도 자유 생성에서 그 문장이 자주 나오지는 않을 수 있습니다.

## 실행과 기록

실습 루트(`toy-lm/`)에서 `npm run compare`를 실행합니다. `results/samples/*.jsonl`에 각 생성 결과를, `results/distributions/*.csv`에 문장별 횟수를 저장합니다. 결과는 Git에서 제외하며 실행으로 재생성합니다.

생성 결과의 `novel`과 원본 그림의 **Novel PPL**은 서로 다른 집계입니다. 전자는 생성한 결과를 분류한 범주이고, 후자는 미리 정한 평가 문장으로 계산한 예측 점수입니다.
