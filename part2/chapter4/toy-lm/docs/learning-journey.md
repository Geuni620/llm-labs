# 여섯 문장으로 NPLM을 만들고 PPL을 해석하기 — 학습 기록

이번 세션의 목표는 같은 한국어 문장 6개로 트라이그램과 Bengio(2003) 기반 NPLM을 직접 구현하고 비교하는 것이었다. TypeScript와 Node로 순전파·역전파·최적화·시각화를 구현했다. 외부 실행 라이브러리는 사용하지 않고 TypeScript 타입 검사기와 Node 타입 정의는 개발 도구로 유지했다.

[data](../data/README.md) → [trigram](../trigram/README.md) → [nplm](../nplm/README.md) → [generation](../generation/README.md) 순서로 실제 데이터와 계산을 따라간다.

## 문장 수, 임베딩 차원, 뉴런 수는 다르다

데이터는 주어 3개·과일 3개·동사 2개로 만든 문장 6개다. 일반 단어는 8개이고 특수 토큰을 포함한 어휘는 11개다. 각 문장에서 예측 문제 4개를 만들어 총 24쌍을 학습한다.

2차원 임베딩은 단어마다 숫자 2개를 학습한다는 뜻이다. 입력 단어가 2개이면 은닉층 입력은 숫자 4개다. 은닉 뉴런 H는 별도로 정하고, 출력 뉴런 수는 전체 후보 토큰 수 V=11로 정한다.

H=6인 예에서는 입력→은닉 연결 가중치가 4×6=24개다. 실제 비교 실험은 H=8이며, 입력→은닉 연결 32개와 은닉→출력 연결 88개가 있다. 임베딩과 편향까지 총 161개 숫자를 학습한다.

NLM은 신경망 언어 모델의 넓은 명칭이고, 이번 NPLM은 그 안의 피드포워드 구조다. 신경망이라는 개념은 언어 모델보다 넓다.

## loss는 틀린 비율이 아니다

정답 확률이 40%인 설명용 예시에서 크로스 엔트로피는 `-ln(0.4) ≈ 0.9163`이다. 정답에 높은 확률을 줄수록 loss는 0에 가까워진다. 가장 높은 확률의 후보가 틀렸다고 loss가 곧 100%가 되지는 않는다.

softmax와 loss도 구분했다. 0.6과 0.4가 확률 이전의 출력 점수인 logit이면 softmax를 거쳐 약 54.98%와 45.02%가 된다. 이미 확률인 60%와 40%를 loss에 사용할 때는 다시 softmax에 넣지 않는다.

## 역전파는 기울기를 구하고, 경사하강법은 값을 바꾼다

```text
순전파 → loss 계산 → 역전파로 각 기울기 계산 → 경사하강법으로 갱신
새 값 = 기존 값 - 학습률 × 기울기
```

역전파는 각 가중치가 loss에 미치는 영향을 연쇄법칙으로 계산한다. 임베딩도 갱신하며, 같은 단어에서 온 기울기는 공유 임베딩 행에 합산한다. 모든 기울기를 기존 가중치로 계산한 뒤 갱신한다.

가중치 1, 기울기 -4일 때 학습률 0.01이면 1.04, 학습률 0.1이면 1.4가 된다. 학습률은 같은 기울기에 대한 수정량에 곱하는 배율이다. 가중치를 항상 늘리거나 줄이는 설정은 아니다.

한 번 전체 데이터를 사용하는 것이 1에포크다. 현재는 24쌍 전체의 평균 기울기로 한 번 수정하는 full-batch GD이므로 1에포크당 갱신도 1회다. SGD·미니배치·Adam은 이번 구현과 구분했다.

## 학습률을 바꿀 때 무엇을 비교했나

같은 D와 seed에서는 초기 가중치를 같게 두었다. D=2, H=8, 2,000회 갱신에서 다음 결과를 얻었다.

| 학습률 | 최종 학습 PPL 평균 | 생성된 새 조합 | 오류·미완성 |
| --- | ---: | ---: | ---: |
| 0.05 | 1.5983 | 1.86% | 5.22% |
| 0.1 | 1.5780 | 0.67% | 2.43% |
| 0.3 | 1.5688 | 0.17% | 0.90% |
| 1.0 | 1.5662 | 0.08% | 0.25% |

PPL은 학습 seed 123·456·789의 평균이다. 생성 비율은 seed 123으로 학습한 모델 하나에서 추첨 seed 2026으로 10,000개를 생성한 결과다. 학습률이 클수록 항상 좋다는 뜻은 아니며, 이 데이터와 학습 횟수에서 관측한 결과다.

전체 비교는 D=1·2·3, 학습률 4개, 학습 seed 3개로 총 36회 학습했다. 신경망 12설정과 트라이그램 2종에서 각각 10,000개씩 총 140,000개를 생성했다.

## PPL 1.5661은 무엇을 의미하나

```text
평균 loss = mean(-ln(각 정답 토큰의 확률))
PPL = exp(평균 loss)
정답 확률의 기하평균 = 1 / PPL
```

기하평균은 여러 확률을 곱한 뒤 그 개수만큼의 제곱근을 취한 값이다. PPL 1.5661은 정답 확률의 기하평균 약 63.85%에 해당한다. 예측을 몇 개 맞혔는지를 세는 정답률이나 확률의 산술평균과는 다르다.

직관적으로는 동등한 확률의 후보 약 1.57개 가운데 하나를 고르는 정도의 불확실성으로 환산할 수 있다. 실제 출력 후보는 계속 11개다.

NPLM의 최저 단일 실행은 D=2, H=8, lr=1.0, seed=123, 2,000회 갱신이었다. 평균 loss는 약 0.448579, PPL은 **1.566086**이다. 같은 설정의 세 seed 평균 PPL은 **1.566199**다.

관측 문맥별 확률을 자유롭게 맞추는 MLE의 최적 학습 PPL은 **1.565085**다. 이 데이터에서는 각 관측 문장의 최적 전체 확률이 1/6이고 문장당 예측이 4회여서 `exp(ln(6)/4)`로도 확인한다.

같은 문맥 `(<bos>, 철수는)` 다음 토큰으로 사과를과 딸기를 모두 학습한다. 양쪽에 각각 100%를 줄 수 없으므로 최적으로 맞춰도 평균 loss는 0보다 크고 PPL은 1보다 크다.

낮은 PPL은 평가 문장의 실제 다음 토큰에 높은 확률을 줬다는 뜻이다. 모델 스스로의 확신만을 나타내는 지표는 아니다. 정답에 0%, 오답에 100%를 주면 오답에 확신하지만 PPL은 이론적으로 무한대다.

## 스무딩의 k와 학습률은 다르다

add-k는 모든 후보의 관측 횟수에 k를 더하고 분모에 kV를 더한다. 관측되지 않은 후보에도 확률을 주는 고정 계산 규칙이며, 경사하강법으로 가중치를 움직이는 학습률과 구분한다.

`(철수는, 사과를)` 뒤에는 좋아해만 한 번 관측했다. V=11, k=0.01이면 좋아해는 `1.01/1.11 ≈ 90.99%`, 나머지 후보 각각은 `0.01/1.11 ≈ 0.90%`다. k=0.5이면 좋아해는 약 23.08%, 나머지는 각각 약 7.69%다.

k가 커질수록 이 분포는 균등 분포에 가까워진다. 관측 문장의 적합도, 미관측 후보의 확률, 생성 오류 비율을 함께 봐야 한다.

## 생성 결과의 Novel과 그림의 Novel PPL을 구분했다

10,000개 생성 실험에서는 모델이 만든 문장 중 원문에 없고 형식이 맞는 결과를 novel로 분류했다. 대표 NPLM의 새 조합 17회는 6종이 중복을 포함해 나온 횟수다. 원문 불일치 107회에는 오류 90회도 포함되어 있었다.

사용자가 가져온 원본 실험 7 그림의 파랑·빨강은 둘 다 PPL이다. 원본 ZIP의 `experiments/exp7_perplexity.py`를 압축 해제 없이 읽어 확인했다.

- **Train PPL:** 학습 문장 6개로 평가한다.
- **Novel PPL:** 작성자가 미리 정한 아래 문장 3개로 평가한다.

```text
철수는 바나나를 좋아해
짱구는 사과를 싫어해
영희는 사과를 싫어해
```

이 세 문장은 모델의 자유 생성 결과를 모은 것이 아니다. Novel은 학습에 없던 평가 문장이라는 뜻이다.

원본의 k=0 트라이그램은 이 문장들을 나눈 12개 예측 중 3개 정답에 확률 0을 줬다. 수학적으로는 PPL이 무한대지만, 원본 `python/ngram.py`가 평가 시 확률을 최소 `1e-30`으로 바꾼다. 그 계산을 재현하면 **103,892,183.68011698**로, 그림의 약 1억과 일치한다.

큰 PPL은 정답에 매우 낮은 확률을 줬다는 결과다. 후보 사이에서 망설였다는 뜻만은 아니다. 이 그림의 수치는 원본 Python 실험이며, 이번 TypeScript 실험의 학습 PPL과 구분한다.

평가의 목적도 구분한다. 학습에는 `영희는 사과를 좋아해`가 있는데 위 평가에서는 같은 조합에 `싫어해`를 요구한다. 문장이 형식상 자연스러운지, 관측한 분포를 재현하는지, 새로운 조합을 예측하는지는 서로 다른 평가 목적이다. 높은 Novel PPL만으로 모델의 전반적인 성능이 나쁘다고 단정하지 않는다.

## 새 조합이 많으면 더 잘 배운 것일까

대표 설정에서 트라이그램 add-k(k=0.01)의 새 조합은 42회, NPLM은 17회였다. 오류·미완성도 각각 1,890회와 90회로 차이가 컸다.

NPLM은 `(철수는, 바나나를)` 다음 좋아해에 약 99.89%를 주었지만, 자유 생성에서 먼저 그 문맥에 도달할 확률은 작았다. `(<bos>, 철수는)` 다음 바나나를이 약 0.22%였기 때문이다. 다음 토큰의 조건부 확률과 전체 문장 확률을 구분했다.

생성할 때는 가중치를 고정하고 확률에 비례해 다음 토큰을 추첨한다. 원본 문장을 검색하지 않는다. 원문과 같다는 사실만으로 검색했다고 판단할 수 없으며, 원문과 다르다는 사실만으로 올바른 일반화라고 판단할 수도 없다.

## 확인한 범위와 다음 실험

학습용 저장소의 파일 수를 줄이기 위해 일반 테스트와 브라우저 QA 파일을 두지 않고 `npm run gradcheck` 하나를 남겼다. 실제 24쌍을 사용해 D=1·2·3, H=8의 모든 변수 성분에서 수치 미분과 직접 계산한 역전파를 대조한다. 타입 검사는 별도로 수행한다.

`npm run animate`로 대표 설정의 전체 가중치 101시점과 loss 2,001개를 기록한다. `npm run explain`은 현재 소스에서 코드 발췌와 해설을 재생성한다. 실행·학습·시각화에는 외부 패키지가 없으며 TypeScript와 Node 타입 정의는 개발용으로 남겼다.

후속 실험은 일부 문장을 학습에서 빼고 평가하기, H=6·8 비교, 여러 생성 seed의 비율 편차 확인이다. SGD·미니배치·Adam을 추가한다면 갱신 횟수와 학습 예시 노출 수를 함께 비교한다. 학습 데이터의 낮은 PPL과 별도 평가 데이터의 성능은 나누어 기록한다.
