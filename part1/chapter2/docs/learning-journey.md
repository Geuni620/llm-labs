# 바이그램인데 왜 한 글자씩 붙지? — 한국어 N-gram 실습 기록

이번 세션의 목표는 한국어 데이터로 문장을 만들면서 N-gram의 동작을 이해하는 것이었다. 대화에서 생긴 질문을 실제 데이터의 횟수와 생성 결과로 확인했다.

출발점은 “바이그램이면 두 글자씩 나와야 하는 것 아닌가?”였다. 마지막에는 N=5, 7, 10으로 문장을 생성하고, 문맥을 길게 볼수록 원문을 재현하는 결과가 많아지는 것을 관찰했다.

## 먼저 어떤 데이터를 쓰는지 확인했다

[Chatbot_data](https://github.com/songys/Chatbot_data)의 한국어 문답 11,823개 중에서 일상 대화에 해당하는 `label=0`의 답변 `A`를 골랐다.

```text
원본 문답 11,823개
  -> 일상 답변 5,290개
  -> 중복 답변 2,910개 제거
  -> 학습용 고유 답변 2,380개
```

중복은 **정규화한 답변 전체가 같은지**로 판단했다. 같은 답변을 한 번만 남겼고, 원본 CSV는 보존했다. 데이터의 불필요한 문자를 점검했지만, 이번 데이터에서 실제로 제거된 답변 행은 중복 2,910개였다.

여기서 2,380개는 답변의 수다. 한 답변에서 여러 글자 묶음이 나오므로 N-gram의 수는 따로 센다. 실제 바이그램은 총 30,176회 관측됐고, 서로 다른 묶음은 5,157개였다.

정제 과정은 [보고서](../data/cleaning_report.json)에 남겼다. 이후의 모든 빈도표는 같은 [정제본](../data/daily_answers.txt)을 사용했다.

## 두 글자의 묶음은 한 글자씩 겹친다

바이그램은 연속한 두 글자의 묶음이다. `하세요.`를 한 글자씩 이동하며 읽으면 다음과 같다.

```text
하세 / 세요 / 요.
```

문장을 생성할 때는 이미 있는 앞 글자를 공유한다. 따라서 매 단계에서 새 글자 하나를 추가한다.

```text
하 -> 하세 -> 하세요 -> 하세요.
```

N=2는 마지막 한 글자를 보고 다음 글자를 고른다. N=5는 마지막 네 글자, N=10은 마지막 아홉 글자를 본다. 일반적으로 **앞의 N-1글자를 참고해서 다음 한 글자를 고르는 것**이다.

공백과 문장부호도 한 글자로 셌다. 화면의 `␣`는 공백 하나를 눈으로 확인하기 위한 표시다. 각 답변 안에서만 묶음을 세고, 서로 다른 답변 사이를 이어 붙이지 않았다.

## 확률의 분모는 같은 문맥 뒤의 전체 횟수다

“하 다음에 가장 많이 나온 글자는 무엇인가?”를 전체 학습 데이터에서 조회했다.

| 다음 글자 | 묶음 | 횟수 | 같은 문맥 뒤의 전체 횟수 | 확률 |
| --- | --- | ---: | ---: | ---: |
| 세 | 하세 | 104 | 559 | 18.60% |
| 루 | 하루 | 5 | 559 | 0.89% |

```text
P(세 | 하) = '하세'의 횟수 / '하' 뒤에서 관측한 전체 횟수
          = 104 / 559
```

분모는 전체 답변 2,380개가 아니다. **문맥이 `하`인 경우의 다음 글자 횟수를 모두 합친 559**다. 한 문장만 센 예시와 전체 데이터에서 센 확률도 구분해야 했다.

상위 10개를 조회하는 것은 화면에 보여주는 개수를 제한하는 것이다. 모델의 빈도표에는 관측된 전체 후보를 저장했다. N=1, 2, 3, 4, 5, 7, 10의 표를 각각 구분해 보관했다.

## 확률을 구한 뒤에는 선택 방법을 정했다

생성기에는 두 가지 선택 방법을 구현했다.

- `greedy`: 해당 문맥에서 가장 많이 나온 다음 글자를 고른다.
- `sample`: 후보마다 등장 횟수만큼 추첨 기회를 준다.

최대 빈도 선택으로 `하`에서 시작했을 때는 `하세요.`가 나왔다. 확률 추첨에서는 같은 문맥에서도 다른 후보를 고를 수 있다. 18.60%로 가장 자주 나온 `세`가 매번 선택되는 것은 아니다.

생성 결과와 함께 문맥, 후보별 횟수, 분모, 확률, 선택한 글자, 누적 문장을 기록했다. 추첨에는 티켓도 남겼다. 같은 데이터·설정·seed를 쓰면 배치 전체를 같은 순서로 재현할 수 있다.

## N을 늘렸더니 원문 재현이 많아졌다

시작 문구를 `마음이 조급해지면`으로 고정했다. seed는 42, 최대 길이는 100글자였다. 횟수에 비례해 추첨하고, N별로 10개씩 생성했다.

| N | 참고하는 문맥 | 서로 다른 결과 | 학습 답변 전체와 일치한 결과 |
| --- | --- | ---: | ---: |
| 5 | 마지막 4글자 | 5/10 | 4/10 |
| 7 | 마지막 6글자 | 3/10 | 6/10 |
| 10 | 마지막 9글자 | 2/10 | 10/10 |

N=5에서는 이런 문장이 나왔다.

> 마음이 조급해지면 하지 말고 형편에 맞게 넣으세요.

글자들은 이어졌지만, 무엇을 넣으라는 것인지는 문장만 읽어서 알기 어렵다. 이번 모델은 문장의 의미를 평가하는 기능 없이 글자 묶음의 빈도로 다음 글자를 선택했다.

N=10에서는 다음과 같이 학습 데이터에 있던 답변이 그대로 나왔다.

> 마음이 조급해지면 자꾸만 악수를 둘 가능성이 높아집니다.

이번 데이터에서는 긴 문맥 뒤에 후보가 하나만 남는 경우가 많았다. 그 지점에서는 추첨해도 같은 글자를 고르게 된다. **현재 데이터와 시작 문구에서는 N이 커질수록 원문 재현이 늘었다.** 다른 시작 문구나 처음 보는 답변에서도 같은 결과가 나올지는 별도로 확인해야 한다.

학습 데이터는 이미 중복을 제거했다. 생성 결과의 반복은 같은 경로를 다시 추첨한 것이다. 10번의 결과를 그대로 기록해서, 서로 다른 결과가 얼마나 나왔는지 함께 비교했다.
