# 글자 단위 N-그램 문장 생성 계획

## 목표와 현재 기준

다음 글자를 고르는 과정을 대화에서 한 단계씩 확인하고, 글자들이 이어져 문장이 만들어지는 것을 관찰합니다.

- 입력: `data/daily_answers.txt`의 정제된 일상 답변 2,380개
- 단위: 한글 한 음절, 공백, 문장부호 등을 포함한 Unicode 글자 하나
- 현재 자료: N=1, 2, 3, 4, 5, 7, 10의 전체 빈도표 `counts.csv`
- 현재 단계: 최대 빈도 선택, 가중 추첨, 일반 N, 배치 생성과 시드가 구현되어 있습니다. N=5, 7, 10에서 각각 10개를 생성했습니다. 시작·끝 표시와 짧은 문맥 대체는 4단계의 추가 학습 계획입니다.

각 단계는 작은 예시를 확인하고, 실제 데이터에서 같은 계산을 보고, 결과와 개선점을 이야기한 뒤 다음 단계로 진행합니다.

## 실행한 실습 — N=5, 7, 10에서 문장 10개 생성

2026-10-14에 일반 N과 확률 추첨을 구현하고 실행했습니다. 공통 접두어는 공백 포함 9글자인 `마음이 조급해지면`, 시드는 42, 최대 길이는 100글자입니다.

- N=5: 마지막 4글자, 서로 다른 결과 5/10, 원본 답변과 일치 4/10
- N=7: 마지막 6글자, 서로 다른 결과 3/10, 원본 답변과 일치 6/10
- N=10: 마지막 9글자, 서로 다른 결과 2/10, 원본 답변과 일치 10/10

30개 모두 문장부호에서 종료했습니다. [실행 방법과 결과](README.md), [비교 기록](../ngram/comparison_n5_n7_n10.json)을 확인합니다.

27개 테스트와 실제 출력 검증에서 문맥 길이, 한 글자씩 추가, 추첨 구간, 배치 재현을 확인했습니다. 원문 재현 여부도 함께 기록했습니다.

## 이전에 정한 비교 기준 — 같은 시작 문구에서 문장 10개 생성

2026-10-13 당시 생성기는 N=2의 `greedy` 방식만 지원했습니다. 기존 바이그램 표에서 다음 세 접두어를 넣으면 모두 비슷한 끝부분으로 이어졌습니다.

```text
오늘은 → 오늘은 거예요.
지금은 → 지금은 거예요.
하루가 → 하루가 거예요.
```

이때 정한 범위는 **같은 바이그램에서 확률에 따라 다음 글자를 추첨해 문장 10개를 생성하는 것**이었습니다. 이후 요청에 따라 동일한 추첨 기능을 N=5, 7, 10에 적용했습니다.

1. 데이터는 정제된 답변 2,380개와 기존 바이그램 표를 사용합니다.
2. N=2, 접두어 `오늘은`, 최대 길이 100글자로 조건을 고정합니다.
3. 매 단계에서 마지막 한 글자를 조회하고, 전체 후보의 등장 횟수를 가중치로 다음 한 글자를 추첨합니다.
4. `.`, `!`, `?`가 나오면 종료하고, 후보가 없거나 최대 길이에 도달하면 그 이유를 기록합니다.
5. 한 배치의 시작에 시드 42를 설정하고, 이어지는 하나의 난수 흐름으로 10개를 생성합니다. 같은 데이터와 설정으로 전체 배치를 재현할 수 있게 합니다.
6. 같은 접두어의 최대 빈도 결과 하나와 추첨 결과 10개를 함께 읽고 비교합니다.

첫 생성 문장 하나에서는 문맥, 후보별 횟수와 분모, 선택한 글자와 데이터 비율, 누적 텍스트를 자세히 봅니다. 그다음 나머지 9개를 확인합니다. 화면에 후보 10개를 표시하더라도 실제 추첨은 전체 후보를 사용합니다.

비교할 항목은 서로 다른 결과 수, 반복되는 글자·표현, 종료 이유, 원문 답변과 동일한 결과, 직접 읽었을 때의 자연스러움입니다. 짧거나 중단된 결과도 그대로 기록해 선택 방식의 영향을 확인합니다.

생성 문장 목록과 선택 기록은 `bigram/generation/`에 추첨 결과용 파일로 저장합니다. 문맥을 늘리는 실습에서는 `trigram/generation/`, `ngram/n4/generation/`에 같은 형식으로 저장합니다.

이 범위를 확인한 뒤에는 동일한 접두어와 데이터로 N=3, N=4를 비교하고, 마지막으로 시작·끝 표시와 짧은 문맥 대체를 추가합니다. 아래의 2~4단계가 그 순서에 해당합니다.

## 1단계 — 바이그램에서 최대 빈도로 한 글자씩 생성

기존 `bigram/counts.csv`를 사용합니다. 첫 접두어는 `하`, N은 2로 고정합니다.

1. 누적 텍스트의 마지막 한 글자를 문맥으로 조회합니다.
2. 그 문맥에서 가장 많이 나온 다음 글자 하나를 고릅니다.
3. 선택한 글자를 붙이고, 마지막 글자를 새 문맥으로 사용합니다.
4. 처음 나온 `.`, `!`, `?`에서 종료합니다. 최대 길이는 접두어를 포함해 100글자로 제한합니다.

현재 표에서 확인한 선택 흐름은 다음과 같습니다.

```text
하     → 세 선택 → 하세
하세   → 요 선택 → 하세요
하세요 → . 선택  → 하세요.
```

- `하 → 세`: 104 / 559, 약 18.60%
- `세 → 요`: 854 / 881, 약 96.94%
- `요 → .`: 1,989 / 2,140, 약 92.94%

이 세 단계의 수치는 2026-10-11에 기존 빈도표와 실제 생성기에서 확인했습니다. 실행 방법과 결과는 [1단계 실습](README.md)에 정리했습니다.

매 단계에서 문맥, 후보 글자와 횟수, 분모, 선택한 글자, 선택 확률, 누적 텍스트를 보여줍니다. 조회 화면의 후보 수는 출력만 제한하며, 전체 후보는 모델에 유지합니다.

같은 빈도의 후보는 최초 데이터 등장 순서로 선택합니다. 반복되는 조합도 추적 로그에 남겨, 최대 빈도를 계속 선택할 때 어떤 문제가 생기는지 확인합니다.

종료 이유는 `punctuation`, `max_length`, `unseen_context`로 기록합니다. 후보가 없는 문맥과 길이 제한에 도달한 경우에는 그때까지 만든 텍스트와 이유를 함께 보여줍니다.

이 단계의 문장부호 종료는 기초 실습용 규칙입니다. 뒤 단계에서는 데이터에서 끝나는 위치를 학습하도록 개선합니다.

## 2단계 — 같은 바이그램에서 확률에 따라 추첨

N=2와 같은 빈도표를 유지하고, 다음 글자 선택 방법을 바꿉니다.

- `greedy`: 가장 높은 확률의 후보 선택
- `sample`: 전체 후보의 등장 횟수를 가중치로 추첨

예를 들어 `하` 뒤에서는 `세`도, `루`도 후보입니다. 추첨 방식에서는 각각 104 / 559, 5 / 559에 해당하는 확률로 선택할 수 있습니다.

시드를 지정해 같은 실행을 재현합니다. 같은 접두어 `오늘은`에서 최대 빈도 결과 하나와 추첨 결과 10개를 비교합니다. 이 단계에서는 반복, 문장 끝맺음, 원문을 그대로 재현하는 사례를 직접 읽어봅니다.

## 3단계 — N을 바꿔 문맥 길이 비교

먼저 같은 접두어 `오늘은`으로 바이그램과 트리그램을 비교합니다.

- N=2는 마지막 글자 `은`을 조건으로 다음 글자를 고릅니다.
- N=3은 마지막 두 글자 `늘은`을 조건으로 다음 글자를 고릅니다.

그다음에는 같은 접두어로 N=4까지 늘리고, 유니그램을 앞 문맥 없는 기준으로 비교합니다. `오늘은`은 세 글자여서 N=4의 문맥도 채울 수 있습니다. `지금은`, `하루가`에서도 같은 비교를 반복합니다. 세 접두어의 시작 문맥이 N=2, 3, 4의 현재 빈도표에 존재하는 것을 확인했습니다.

- N=1: 앞 문맥 없이 전체 글자 빈도에서 선택
- N=2: 마지막 한 글자
- N=3: 마지막 두 글자
- N=4: 마지막 세 글자

이 단계에서는 접두어를 그대로 두고 그 뒤의 글자를 생성합니다. 생성 시작 시 N-1글자보다 짧은 접두어는 오류로 알려줍니다. 시작 표시를 사용하는 생성은 다음 단계에서 추가합니다.

데이터, 선택 방법, 접두어, 길이 제한을 맞추고 비교합니다. 높은 N에서 원문을 그대로 이어 쓰는 현상도 관찰합니다. 생성 예시만으로 새 문장을 잘 예측하는 능력을 판단하지 않습니다.

## 4단계 — 시작과 끝, 관측되지 않은 문맥 개선

### 시작·끝 표시 학습

답변 앞에 시작 표시 N-1개, 뒤에 끝 표시 하나를 넣어 학습합니다. 특수 표시는 한 단위로 취급하고 출력 문장에는 넣지 않습니다. N=2에서 `하루`의 연결은 다음과 같습니다.

```text
시작 → 하 → 루 → 끝
```

이후에는 접두어 없이 시작 표시에서 출발하거나, 사용자가 준 접두어 뒤를 생성할 수 있게 합니다. 끝 표시를 뽑으면 종료합니다.

정제본의 한 줄은 답변 전체이며 여러 문장을 포함할 수 있습니다. 이 끝 표시는 답변 전체의 끝을 학습합니다. 첫 문장만 생성하는 문장부호 종료와 답변 전체를 생성하는 끝 표시 종료의 차이를 설명하고 비교합니다.

시작·끝 표시가 추가되면 문맥별 분모도 바뀔 수 있으므로, 생성용 빈도표와 설정은 별도 파일에 저장합니다. 기존 `counts.csv`는 실제 글자 묶음만 센 기준표로 사용합니다.

### 짧은 문맥으로 돌아가기

관측되지 않은 문맥을 만나면 마지막 N-2글자로 줄여 다시 조회합니다. 필요한 경우 유니그램까지 내려가며, 어느 N으로 선택했는지 로그에 남깁니다. 먼저 후보가 없어서 멈춘 사례를 확인한 뒤 이 개선을 적용합니다.

최대 길이 제한은 끝 표시와 함께 계속 사용합니다.

## 파일과 실행 방법

- `generation/generate.py`: 1단계의 조회, 최대 빈도 선택, 문맥 갱신, 종료
- `generation/test_generate.py`: 손으로 확인할 수 있는 생성 사례 검증
- 각 N의 폴더: 생성 예시와 한 글자씩 선택한 기록 저장
- 시작·끝 표시를 추가하는 단계: 생성용 빈도표와 데이터 해시, 종료 설정도 저장

현재 실행할 수 있는 1단계 명령입니다.

```sh
python3 part1/chapter2/generation/generate.py --n 2 --prefix 하 --method greedy --max-chars 100 --trace
```

아래 명령도 같은 생성기로 실행할 수 있습니다. N이 커지면 그에 맞는 길이의 접두어를 사용합니다.

```sh
python3 part1/chapter2/generation/generate.py --n 2 --prefix 오늘은 --method sample --seed 42 --count 10
python3 part1/chapter2/generation/generate.py --n 3 --prefix 오늘은 --method sample --seed 42 --count 10
```

각 실험의 첫 문장 선택 기록을 대화에서 확인하고, 다른 문맥이나 접두어로 추가 비교합니다.

## 단계별 검증

- 작은 데이터로 직접 계산한 후보 횟수와 분모가 일치하는지 확인합니다.
- 바이그램은 마지막 한 글자, 트리그램은 마지막 두 글자로 문맥을 갱신하는지 확인합니다.
- 추첨 구간을 고정한 예시로 2:1 같은 가중치의 선택 경계를 검증합니다.
- 같은 시드와 입력, 설정으로 같은 추첨 결과가 나오는지 확인합니다.
- 한 배치의 난수 흐름을 사용하고, 동일 설정의 배치가 문장 순서까지 재현되는지 확인합니다.
- 문장부호, 최대 길이, 후보 없는 문맥, 반복되는 연결의 종료 기록을 확인합니다.
- 시작·끝 표시를 추가한 뒤에는 경계 학습, 짧은 답변, 특수 표시의 출력 제외를 확인합니다.
- 실제 데이터에서는 단계별 선택 기록으로 최종 텍스트를 다시 따라갈 수 있는지 확인합니다.

예측 성능을 비교하는 실험은 별도 단계에서 같은 학습·평가 분할로 진행합니다. 현재 계획의 첫 목적은 글자 선택이 이어져 문장이 되는 과정을 이해하는 것입니다.
